# AI 辅助开发 RISC-V CPU：提示词撰写指南（aihelper.md）

> 本指南配合 `RISC-V-CPU-2026/docs/CPU开发流程.md` 使用，告诉你**怎么给 AI 下指令**，让 AI 高效、正确地协助完成 CPU 2026 课程项目。
> 适用工具：ChatGPT / Claude / GitHub Copilot / opencode / Cursor 等任意支持长对话与代码生成的 AI。

---

## 0. 先读课程 AI 政策

- AI 辅助编码**被允许**，但 Code Review 会重点考察：**架构设计细节、模块级权衡、与 LLM 的交互记录**。
- 结论：**AI 是加速器，不是替身**。你的目标是"AI 写代码，你能逐行讲清楚为什么"。每次让 AI 做完一件事，必须要求它解释设计决策，并把这些解释沉淀成自己的笔记（也是答辩素材）。
- 建议全程保留对话记录（导出对话/截图），这是政策明确要求展示的东西。

---

## 1. 提示词写作五条铁律

1. **一次只让 AI 做一件事**：一个模块、一个 bug、一次分析。一次生成 2000 行 RTL 的结果是"能编译但没人敢改"。
2. **先喂上下文，再给任务**：让 AI 先读 `docs/axi4-lite.md`、`docs/sram.md`、`README-ZH.md`，再谈代码。否则它会用"教科书 AXI"和"教科书 RISC-V"（含你不需要的 CSR、非对齐、burst 等）凭空发挥。
3. **把硬约束写成清单**：接口信号名、握手规则、复位行为、地址范围、退出协议。约束越具体，幻觉越少。
4. **先方案后代码**：让 AI 先给设计草案 + 权衡，你确认后再让它写代码。既防返工，又沉淀 Code Review 素材。
5. **验收闭环**：每个任务都附上验证命令（`make build` / `make test Case=...` / `make synth`），把报错原样回喂，直到通过。

```text
【上下文】项目背景：RISC-V CPU 课程（CPU 2026）。请先阅读以下文档，严格遵守其中的规范：

  - RISC-V-CPU-2026/docs/CPU开发流程.md（当前所处阶段）
  我已实现的模块：<已有模块名与文件路径，例如 verilog/decoder.sv>。

【任务】<一句话说清楚要做什么，例如：编写 AXI4-Lite Master 适配模块>。

【约束】（逐条列出，非协商）
  1. 模块名/端口/参数必须为：<粘贴精确接口定义>
```

## 3. 分阶段提示词库（可直接改着用）

### 阶段 0–1：学习与架构设计

**让 AI 讲协议/规范**（先建立共同认知）：

```text
请阅读 RISC-V-CPU-2026/docs/axi4-lite.md 与 scripts/sim.cpp，然后回答：
1. 内存从机各通道队列深度多少？服务节奏与响应延迟如何？
2. 程序如何终止？仿真器在哪一拍捕获返回值？
3. 画出一次读事务与一次写事务的时序图（文字版），标出我 CPU 侧必须遵守的握手约束。
4. 列出最容易导致死锁的 5 种错误写法。
```

**让 AI 出架构设计文档**：

```text
请先不要写代码。目标：RV32IM 乱序执行 CPU（要求：操作数就绪即乱序发射、ROB 按序提交；
发射宽度/ROB 深度/PRF 大小/保留站深度/Cache 参数必须参数化）。
请给出：
1. 流水线框图（文字版）与各模块职责、模块间接口信号草案；
2. 重命名与恢复方案对比（RAT checkpoint vs ROB 回放）：复杂度、面积、恢复延迟；
3. 访存顺序方案（Store Buffer 结构、load 转发规则）；
4. 分阶段实施顺序建议（从最小可运行内核到 OoO 的 5 个里程碑）。
输出为 Markdown，每个方案附 2-3 句权衡说明（这是我要写进报告的素材）。
```

### 阶段 2：最小可运行 CPU

**AXI4-Lite Master 适配器**（本项目第一个硬骨头）：

```text
【任务】编写 SystemVerilog 模块 axi_master，实现 CPU 内部请求到 AXI4-Lite 五通道的转换。
【接口】CPU 侧：
  input  valid_rd, [31:0] rd_addr;  output [31:0] rd_data; output rd_done;
  input  valid_wr, [31:0] wr_addr, [31:0] wr_data, [3:0] wr_wstrb; output wr_done;
  AXI 侧信号名与方向与 docs/axi4-lite.md 的 student_top 模板完全一致。
【约束】
  1. valid 拉高后保持到握手完成；valid 不得组合依赖 ready；
  2. AW 与 W 通道可独立握手，但两者都握手后从机才处理写；必须等 B 响应才置 wr_done；
  3. rready/bready 只要对应 FIFO 有空间就必须能接收，任何情况下不得因内部状态死锁；
  4. 读写事务可并行；队列深度用 parameter（默认 4）；
  5. 复位高电平有效，复位期间全部输出为 0。
【输出】完整 .sv 文件 + 握手状态机设计说明（为什么这样能保证不死锁）。
【验证】make build 无错误。
```

**译码器**：

```text
【任务】编写 RV32IM 译码模块 decoder（SystemVerilog）。
【输入】[31:0] instr；【输出】结构体或展开端口：opcode 分类、rs1/rs2/rd、立即数（I/S/B/U/J 五种格式）、
  funct3/funct7、ALU 操作码、是否访存/分支/跳转/乘除、load 类型（LB/LBU/LH/LHU/LW）、store 类型（SB/SH/SW）、
  非法指令标志（遇到 CSR/FENCE/ECALL/EBREAK 或未实现编码时置位）。
【约束】
  1. 按 RISC-V 规范，注意 S/B/J 立即数的位拼接；SLTIU 用无符号比较；
  2. 非法指令标志置位时 CPU 应停止提交（按 README 要求这些指令不出现，标志仅用于自检）；
  3. 覆盖 M 扩展全部 8 条指令（MUL/MULH/MULHSU/MULHU/DIV/DIVU/REM/REMU），区分符号组合。
【输出】完整 .sv 文件 + 一张"我覆盖了哪些指令"清单。
【验证】make build 无错误；我会用自编测试逐条指令验证。
```

**退出协议检查**（防丢分的最后一关）：

```text
请检查我的退出逻辑是否满足框架要求：程序应通过向 0x80000000 执行 wstrb=4'hf 的 32 位 Store 结束，
返回值放 wdata，且仿真器在 bvalid&&bready 握手成功瞬间捕获结果。
我的实现是：<粘贴相关 RTL 或描述>。
问题：1) 是否保证 wstrb 恒为 4'hf？2) B 通道握手完成前 CPU 是否会提前停摆？3) 退出 Store 之前的所有更老指令是否已提交？
```

### 阶段 3：顺序流水线

```text
【任务】在我的 5 级流水线（F/D/E/M/W）上完善冒险处理。
当前代码：<文件路径，粘贴关键段>。
要求：
1. 设计完整转发网络（EX/MEM、MEM/WB → EX），列出每个必须转发的指令对；
2. load-use 必须 stall，并说明 stall 条件与流水寄存器冻结/气泡方案；
3. 分支在 E 级解析，误取指令在 D/E 级 flush；
4. 与 AXI 访存阻塞（响应未回）组合时，保证不破坏数据。
先给出转发/冒险矩阵（Markdown 表格），我确认后再写代码。
```

### 阶段 4：乱序核心

**重命名**：

```text
【任务】设计寄存器重命名模块。方案已定为：PRF + 空闲列表 + RAT，分支恢复用 <RAT checkpoint / ROB 回放>。
【约束】
1. PRF 大小、读/写端口数用 parameter；
2. 旧物理寄存器必须等指令提交后才能释放（请说明空闲列表的"提交时回收"时序）；
3. 分支/异常 flush 时 RAT 恢复与时序（哪个周期生效）；
4. x0 的处理（重命名到固定物理 0 或禁止写）。
先输出：端口定义 + 关键时序说明 + 与 checkpoint/回放方案的配合方式，再写代码。
```

**发射队列（保留站）**：

```text
【任务】编写发射队列模块 issue_queue：每周期最多入队 N 条、出队 M 条（N、M 参数化），
支持唤醒（写回 tag 广播比较）与选择（按 ROB 号最老优先），支持 flush（清空指定 ROB 号之后的条目）。
【约束】写回端口数 W 参数化；唤醒比较器数量与队列深度的关系请说明（面积敏感点）；
被 flush 清除的条目立即让出物理寄存器（说明如何与空闲列表联动）。
先给结构图与面积估算思路，再写代码。
```

**ROB 与按序提交**：

```text
【任务】编写 ROB：按序分配、乱序完成、按序提交，提交宽度参数化。
【约束】
1. 条目含：目标架构寄存器、目标物理寄存器、完成位、异常/分支信息、PC、指令类型；
2. 提交时写回架构寄存器堆并释放旧物理寄存器；写回端口数与提交宽度配合；
3. 分支错误/异常在提交处精确处理，flush 比该 ROB 号年轻的一切（发射队列、取指、后续写回忽略）；
4. 参数化：深度、提交宽度。
先输出状态机与各事件时序表，再写代码。
```

**访存顺序与 Store Buffer**：

```text
【任务】设计 Store Buffer + load 转发。
【约束】
1. store 在提交后才真正写入内存（提交前只在 buffer 内）；
2. load 执行时按程序顺序检查所有更老且未提交的 store：地址已知且完全重叠→直接转发数据；
   部分重叠或不重叠→转发对应字节；地址未知→保守 stall（先正确，后优化）；
3. 说明 store 数据写回 D-cache/AXI 的时机与唤醒等待该 store 的 load 的时序。
先给出"load 转发决策表"与保守顺序方案，再写代码。
```

### 阶段 5：Cache 与 SRAM

```text
【任务】编写 D-cache（sram_fakeram 实现）。参数化：容量、行大小、相联度、写策略（write-back）、替换策略（先伪 LRU 或随机）。
【约束】（docs/sram.md 硬规则）
1. 实例化 sram_fakeram 作为 tag 阵列与数据阵列（数据阵列 WRITE_GRANULARITY=8 支持字节掩码写）；
2. 单端口 1RW：同一周期每阵列只能一读或一写——请明确每周期读写端口分配方案；
3. 读延迟 1 周期：本周期发地址下周期取数，命中路径必须对齐；
4. valid 位用寄存器实现并复位清零（SRAM 无复位引脚）；
5. 单个实例 DEPTH×WIDTH ≤ 16,777,216 位；不要把 sram_fakeram.sv 加进 filelist.f；
6. 支持多 MSHR（数量参数化），miss 期间可服务命中。
先输出：阵列划分、每周期端口分配表、miss 状态机、面积粗算（0.0419904 μm²/位），再写代码。
```

## 5. 调试类提示词模板（高频复用）

**回喂报错**（AI 最擅长的事）：

```text
make build 报错如下：<粘贴完整错误输出>。
相关代码：<文件路径与行号>。请解释报错原因并给出最小修复（只改这一处，不动无关逻辑）。
```

**回归定位（二分法）**：

```text
改动 <描述改动> 后 correctness_add_to_100 从 PASS 变 FAIL，diff 如下：<粘贴 git diff 摘要>。
请判断哪一处改动最可能是根因，并说明依据。不要修改代码。
```

**解释性提问（为 Code Review 储备）**：


## 6. AI 常见翻车点与对策

| 翻车点 | 表现 | 对策 |
| --- | --- | --- |
| 幻觉接口 | 发明 `arsize/arburst`、非对齐访存、CSR 指令 | 提示词里粘贴精确端口模板；要求 AI 先复述接口再写代码 |
| 忽略握手规则 | `valid` 依赖 `ready`、忘等 B 响应 | 把 3 条握手规则写进"约束"段；写完要求 AI 自检 |
| 一次生成太多 | 500 行状态机 + 300 行组合逻辑混在一起，出错难查 | "先方案后代码"+"一次一个模块"；要求输出带明确模块划分 |
| 不按 SRAM 时序 | 把 `sram_fakeram` 当组合读、写周期读 rdata | 约束段写明"读延迟 1 周期、单端口 1RW" |
| 编造性能数字 | 报告里出现"IPC 提升 40%"这类假数据 | 明确要求只用你提供的实测数据 |
| 盲目自信 | 声称"应该没问题"但从不验证 | 每个任务强制附验证命令，PASS 才收工 |
| 修改无关代码 | 修复一个 bug 时重写了三个模块 | 明确"最小改动"；用 git diff 审 AI 的每一处改动 |

## 7. Code Review 准备清单（配合 AI 政策）

1. **保留交互记录**：按阶段/日期整理对话导出（命名如 `2026-10-03_rename_design.md`），放进私有笔记，不进 OJ 仓库或放私有分支。
2. **AI 出题，你作答**：每完成一个模块，用"解释性提问"模板让 AI 生成 5 个审阅问题，自己不看答案作答，再对照 AI 答案——答不出的地方就是复习重点。
3. **你自己重写关键逻辑**：AXI 握手状态机、重命名、ROB 提交至少各手写/复述一遍伪代码。
4. **记录权衡笔记**：每个"方案 A vs 方案 B"的讨论结果（AI 给的对比 + 你的决定理由）整理成表格，直接用于报告"架构探索"章节。

## 8. 一个完整的推荐对话流示例（阶段 2 → 4）

1. **第 1 轮**：贴"六段式模板"，上下文段让 AI 读文档 → 让它输出 axi_master 的设计说明（不含代码）→ 你评审、指出与 sim.cpp 不符处。
2. **第 2 轮**：确认方案 → "现在按该方案输出完整 .sv，并附自检清单" → 你跑 `make build`，报错则回喂。
3. **第 3 轮**：`make run` 通过后 → "写一个覆盖读后写、写后读、连续写的最小自测程序思路" → 手动验证。
4. **第 4 轮**：进入译码器，重复 1–3。
5. **第 5 轮**：集成调试用"回归定位"模板，让 AI 只分析不改码。
6. 每完成一个模块：跑一次"解释性提问"模板，沉淀笔记。
7. 阶段性 commit + tag，把本轮对话导出存档。

> 核心心法：**你负责方向、约束与验收，AI 负责细节、草稿与排查；每一行代码进仓库前，都必须经过你的理解和测试。**
